# Issue #212 自动清理两个开关

本轮仅覆盖节点缓存页“定期清理”和“空间不足时清理”。排除 #129，不合并。

| 范围 | 验收标准 |
| --- | --- |
| 独立修改 | 分别开/关，只发送变化字段，另一开关和其余策略不变 |
| 生效回显 | 节点确认和新快照到达后才切换；进行中不叠加操作 |
| 持久与重复 | 重开页面/重启节点保留；相同请求幂等，无变化不发请求 |
| 失败 | 保留真实状态并允许重试，不以乐观显示冒充成功 |
| 权限与兼容 | 非管理员拒绝；旧节点及不具备有效观察的状态禁用 |
| 保护 | 仅接受两个布尔字段，原阈值、占用、保留、来源、guard和恢复不改 |

自动化只运行 `test_cache_automatic_cleanup_settings.py` 与 Web 的 `automatic cleanup switches` 用例组；类型、格式和改动组件文案检查不涉及其他功能验收。PR继续使用既有CI门禁，不手工扩大到全量业务用例。

本机只操作这两个开关，检查真实快照和持久值，结束恢复原状态；不创建适配器、不执行任务、不触发人工清理或改缓存闲置时间。最终部署SHA、CI、本机结果与截图在PR验收区维护，不能以构建或HTTP成功替代生效确认。
