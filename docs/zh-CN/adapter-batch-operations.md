# 批量启动与停止适配器

[English](../en/adapter-batch-operations.md) · [产品说明](product.md)

在适配器列表进入“批量操作”，勾选要处理的适配器，再选择“批量启动”或“批量停止”。先核对每项将要执行的动作，确认后执行。每批最多 100 项，逐项处理；一项失败不会撤销其他项的结果。

“全选当前列表”只选择当前可见且可编辑的适配器。搜索或筛选隐藏的项会从选择中移除；超过上限时请缩小筛选范围。勾选不切换当前工作台，名称仍可用于打开适配器。

| 运行方式 | 启动做什么 | 停止做什么 |
| --- | --- | --- |
| 手动运行 | 用已保存代码和输入运行一次 | 请求取消本次操作准备时选定的未完成执行 |
| 定时运行 | 启用已有定时配置，不立即额外运行 | 不再产生新的定时执行 |
| Webhook | 开始接收新请求 | 停止接收新请求 |
| 事件触发 | 用已有来源配置开始接收 | 停止新接收，等待监听实际关闭 |

批量操作使用**已保存内容**。编辑区、输入或运行设置中尚未保存的修改不会被提交；运行节点、凭据绑定和运行方式也不会自动替换。停止定时、Webhook 或事件接收不会取消此前已接收的执行，也不会清空积压。手动停止只处理准备时固定的执行，后续新建的执行不会被追着取消。取消请求不能撤销已经发生的外部写入。

## 看懂结果

- **已提交执行**：系统创建了执行记录，可继续查看执行结果；不代表数据处理已经成功。
- **正在停止／已请求取消**：请求已受理，监听或执行尚未确认结束。
- **已停止接收／已停用定时**：对应动作已完成；已接收工作继续按原规则处理。
- **无需变更**：对象已经处于目标状态，不会重复启用。
- **失败**：该项未完成，按原因到适配器中补配置或处理问题。可恢复的失败才提供重试。
- **结果待确认**：连接中断或结果尚不可核对。先重新查询本次操作，不要另起一批重复启动。

“重试失败项”只处理明确失败且仍可操作的项，不重复执行成功项。准备后修改了代码、输入、节点或触发配置时，旧操作会报告配置变化；刷新目录并明确创建新操作，才会使用新配置。需要修复或重新验证身份的事件来源，应先进入该适配器处理，批量启动不会自动重置来源。

刷新页面后可以重新查询本次批量结果。浏览器只保存当前账号的操作标识；服务端查询和每项执行都会核对当前权限。只读适配器不能通过批量入口修改。

## API 与升级

客户端从适配器响应获取 `batch_token`，准备请求传入稳定 UUID、`start|stop` 和 `{adapter_id, expected_token}` 列表：

```text
POST /api/adapter-batches
GET  /api/adapter-batches/{id}
POST /api/adapter-batches/{id}/execute
POST /api/adapter-batches/{id}/retry   {"adapter_ids": [123]}
```

创建只准备计划，execute 才处理尚未提交的项；GET 不执行动作。重复请求须保留原 ID 和原参数，不能把请求超时当成操作失败。每批首期串行提交状态变更，等待真实监听关闭通过查询呈现。

部署需在 0049 后向前应用批量操作记录迁移。升级前备份，沿用原卷、Token 和 Master Key；新增表不改写原适配器或执行。应用回退保留操作记录与既有责任，不通过数据库降级或恢复旧备份清除已发生的工作。此功能不包含批量删除、批量改配置或跨适配器工作流。
