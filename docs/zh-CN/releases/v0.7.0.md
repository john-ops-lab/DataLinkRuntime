# v0.7.0

本版在 v0.6.1 基础上增加事件触发和适配器批量启停，并落实本机代码预审与受保护的 PR 合并流程。

## 主要变化

- **事件触发**：支持 Kafka、Kubernetes、RabbitMQ 和 RocketMQ，配置、启停与接收记录整合在适配器工作台。新建和保存来源不会自动开启接收。
- **可靠接收**：先持久保存消息及处理责任，再确认来源；保留失败、去重、补处理与恢复边界。RocketMQ 的真实账号权限验证，以及 RabbitMQ/RocketMQ 功能关闭后的恢复修复随本版交付。
- **批量启停**：原适配器列表支持多选，每批最多 100 项。手动任务运行一次或取消准备时固定的执行，定时任务启停调度，Webhook 和事件触发启停新接收。使用已保存配置，保留编辑草稿和已有工作，逐项显示部分成功与失败。
- **开发流程**：本机 OCR 预审、核实修复及复审先于提交 PR；main 的期望保护配置要求四项 CI 成功、分支跟上 main、审查讨论解决，并禁止强推和删除，管理员同样受限。高风险改动的人工确认继续由项目规则执行。
- **CI 稳定性**：AI 超时测试在预热 Worker 清理完成后再开始期限断言，避免清理过程污染被测时间窗。

使用说明：[事件触发](../event-subscriptions.md)、[批量操作](../adapter-batch-operations.md)、[本机预审与合并](../local-code-review.md)。

## 已有部署升级

1. 备份数据库与材料数据并验证备份可读。保留原持久卷、挂载、Worker 运行与恢复目录、Token、Master Key 和已有配置。
2. 停止新接收与调度，核对监听关闭、未完成执行及待处理责任。停用接收不会清除已接管数据；不能只用容器健康或队列为空判断责任已结清。
3. 在写入服务停止后切换到 `v0.7.0`，沿用原配置构建新版本镜像，再执行仓库的向前迁移，最后启动 Control、Worker 和 Web。迁移链从 v0.6.1 的 `0046_issue166_retire_ai_history` 依次经过 `0047_issue219_subscriptions`、`0048_issue219_kubernetes`、`0049_issue219_queue_sources`，到 `0050_issue223_adapter_batches`。
4. 核对 schema、服务与 Worker 就绪、保存的配置和已有数据，再恢复已明确选择的调度或接收。事件来源默认关闭；需要使用时，在 Control 配置中显式启用 `DLR_EVENT_SUBSCRIPTIONS_ENABLED`，并单独配置、测试和开启各来源。

已有来源进度、责任与批量操作回执必须保留。旧版 Kubernetes 配置缺少可验证身份时需按来源文档显式建立新接收周期。应用回退前先确认旧程序兼容当前 schema 和责任；不得自动 downgrade、恢复旧库或清空卷来删除已接收工作。测试旧版应用应使用与该版本匹配的独立环境。

从 v0.4.3 或更早版本跨级升级，先核对 [v0.4.4 升级说明](https://github.com/john-ops-lab/DataLinkRuntime/releases/tag/v0.4.4) 中 AI 历史表退役与备份要求。已有缓存自动清理配置继续适用，见[缓存管理](../issue139-cache-governance.md)。

## 验证与边界

- 事件来源实施、真实 Broker/Worker 业务验证、权限与恢复证据归属于 [#221](https://github.com/john-ops-lab/DataLinkRuntime/pull/221) 的具体批次；批量操作与 Kimi OCR 复审证据见 [#225](https://github.com/john-ops-lab/DataLinkRuntime/pull/225)。首败和未验范围保留在对应归档中，不改写为一次全场景通过。
- #225 合并提交 `8963927dbf18d5db1fdd8051fa9f032a28f985a9` 的四项 main CI 已独立通过：[运行记录](https://github.com/john-ops-lab/DataLinkRuntime/actions/runs/40200720720)。本次收尾只改规格、文档和仓库门禁期望配置；最终发布提交及其 CI 以收尾 PR 和 [Release](https://github.com/john-ops-lab/DataLinkRuntime/releases/tag/v0.7.0) 为准，不把前述 CI 冒充发布提交的结果。
- 本地开发环境曾完成前述真实路径验证；GitHub 发布不等于所有用户部署已经升级，也不代表重新运行全部来源、语言、移动端或真实模型矩阵。
- RocketMQ 支持范围为已验的 5.x gRPC Proxy / SimpleConsumer；不外推 4.x、FIFO、事务或云专有协议。Kubernetes 支持范围及历史缺口边界见来源文档。
