## 生命周期与边界

实际 Regenerate 在加入另一份 composer 文件后仍使用旧轮次冻结引用；删除未发送文件不会替换该引用。显式释放旧引用后，界面显示过期并要求新轮次重新附加文件。实际导航离开、返回后，旧引用已过期且临时会话清空；此次 Chrome 返回未命中 BFCache，persisted 恢复分支由专项组件测试及独立审查验证。

删除正在执行 OCR 的附件后，实际转换进程组及临时任务目录消失；没有把前端 AbortSignal 当作进程已终止的证明。独立资源核验以受控故障注入检查转换期限与派生容量边界，失败后存储计量、记录、进程组和许可全部释放，下一次合法转换恢复。并发门禁观测到最多 2 个活动、4 个活动加等待操作；单 worker 转换服务仍可返回真实 busy。上述故障注入结果与默认公开 API 的正常路径分别记录。

两份附件同时选择时曾出现同一页面并行准备导致 busy，已改为最多 8 个存活任务的串行队列；排队删除立即释放任务，关闭页面清空等待任务。最终部署后需核对两份附件无需人工重试即可准备和发送。未知模型组合、部分结构解析、原件缺失缓存及尚未读取页面仍显示实际限制，不把 partial 改成完整成功。
