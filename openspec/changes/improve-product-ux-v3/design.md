# Design

## Context

见 proposal.md。实施依据为已确认 v3 的 28 张图，当前基线 main 7fb4c8f。图册描述产品行为与信息层级，实际字体、间距和控件继续使用现有设计系统，不复制图中示例数据。

## Goals / Non-Goals

**Goals:** 完整保留控件与业务门禁，在原架构内按场景重排、改写提示、提供必要只读查询。

**Non-Goals:** 不重写运行链、AI 提示词或附件处理；不引入 UI 框架；不接入 #129；不改已有数据库。

## Decisions

1. 原组件与回调优先：保留 watcher、草稿、取消、重试与错误处理。运行过程使用可键盘展开区域，异常动作保持可发现。替代方案是删减详情，但会损失排障能力。
2. 按文件拆并行工作：运行/模板、系统管理、AI/账号各拥有组件与独立 CSS，主 Agent 负责 App、common/adapter 语言资源、两个后端查询和集成。避免共同改大样式表。
3. 沿用国际化 namespace，中文使用完整句子，英文独立表达；原始日志/代码/技术标识不翻译或改写。采用 Ant Design 文案规范的用户语言和信息就近原则（https://ant.design/docs/spec/copywriting-cn）。
4. Cron 预览复用服务端现有验证和计算器，认证请求、限制数量，返回 ISO 时间；请求失序及草稿更改必须使旧结果失效。不用浏览器另实现调度算法。
5. 凭据使用查询保持凭据管理的管理员权限，返回真实配置名称/类别，不解密秘密；适配器排除已删除对象。前端仍说明权限范围，空结果不保证全局未使用。
6. 用户管理、新建凭据和自定义服务使用独立弹层；局部表单保持原保存/确认/API行为。知识库测试已保存配置，模型测试当前草稿，各自表达清楚。
7. 图册与原始截图继续私有保存，仓库仅保存无秘密的图号到实现/验证矩阵。公开 Issue/PR 不记录个人部署入口、路径或参数。

## Risks / Trade-offs

- 页面重排导致隐藏入口或状态丢失 → 保留回调并测试展开/关闭/恢复与权限分支，浏览器核对真实页面。
- 中英文说明漂移 → 双语同键和插值检查、英文页面抽验，原诊断信息保持可访问。
- 调度或凭据查询引入新语义 → 仅只读；测试非法输入、权限拒绝、引用准确性和无写入。
- 多模块联动 → 全 Web 检查加具体流程回归；在真实 Worker 完成一次执行，区分 CI、部署及用户验收。

## Migration Plan

无需迁移。PR 当前 HEAD CI 通过后按私有配置更新既有本机验收环境，保留数据、卷与凭据；核对实际部署 SHA、浏览器和真实运行结果。普通控制器与私有 test-acceptance 模式必须先辨识，沿用当前受支持入口。只提交 PR，不合并或发布。

## 用户验收修订

- 删除重复说明和默认技术字段，保留各区域原保存范围与业务门禁。凭据绑定所在编辑区可滚动；输入文件使用局部 border-box 避免撑宽。
- 输入修改比较 JSON 语义；非法值、空字符净化、实际输入方式变化和待保存上传仍需显式保存。同类型重复选择不重置保留期。
- 运行过程先展开，再定位可见内容；换记录使旧定位失效。历史输入快照仍不可变，实时日志原文与操作保留。
- 缓存默认合并限制原因，安装来源确认按需打开；确认仍为管理员提供且有有效期，不冒充自动检测结果。文件托管只整理用量与表单。
- 导入提醒仅在导入缺失输入时出现。成功保存编辑内容、名称描述或输入时，在同一事务内将既有 configuration_notes.review_environment 置为 false；失败不更改，保留来源和许可证。该变更仅维护原有 JSON 元数据，无迁移或接口格式变化。
