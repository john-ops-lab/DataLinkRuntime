# Proposal

## Why

Issue #212：已确认的 v3 图册覆盖 28 个页面场景。当前中英文混杂、内部术语和信息层级使普通用户难以判断结果、下一步操作及保存范围；本次落实图册并保持已有业务行为。

## What Changes

- 执行结果优先；历史日志与实时日志独立；运行过程和文件校验按需展开。
- 编辑、输入与运行配置明确各自保存范围；模板、导出、权限和删除说明贴近操作。
- AI 对话、附件发送反馈、模型配置按任务组织；账号页面完整双语并保留操作。
- 管理页拆分新建与列表，系统检查、缓存来源、文件策略和知识库帮助就近展示。
- 补齐图册所需的两个只读能力：服务端 Cron 时间预览、按权限查看凭据使用位置；不改变已有 API。

## Capabilities

### New Capabilities

- `execution-presentation`：执行结果/过程/日志分层、保存范围、调度预览与运行操作解释。
- `configuration-guidance`：管理表单、凭据引用、配置测试和有效策略的场景化交互。
- `assistant-presentation`：AI 发送范围、本轮附件记录与模型设置的准确反馈。

### Modified Capabilities

无；已有 `managed-input-web` 上传、锁、期限、快照及双语合同继续适用。

## Impact

- 主要修改 Web 组件、局部样式和 zh-CN/en 文案；复用 React 19、Ant Design 5.29.3、ProComponents 2.8.10。
- 后端增加只读预览与凭据引用查询，并按后续授权维护导入提醒与缓存核验；无数据库迁移、依赖升级或执行/调度算法重写。
- 非目标：Issue #129、AI 框架迁移、模型提示词、发布与合并。
- API 鉴权、运行锁、不可变执行快照、凭据保密、上传恢复、清理保护和原始日志保持；保留全部既有操作入口。

用户验收追加九项精简：移除三块保存说明、绑定标题括号和实时日志说明；修复绑定裁切、文件对齐、输入误报及运行过程定位；整理适配器设置、缓存和文件托管；保存后撤下导入提示。后端追加维护既有 configuration_notes 的提醒标志，来源与许可证保留，无迁移或响应格式变更。
- 回退只需回到原软件版本；不变更持久化格式。部署保留既有数据库、卷和凭据；私有参数不入仓库。

用户追加：保存入口改为“保存代码”，无修改禁用，删除按钮下说明；保留首次保存和各独立表单原行为，不修改后端版本 API。

用户追加缓存九项优化：自动核实可重建的普通缓存及其过期证明；突出用量、可清理空间和开关状态；仅选择可清理项并预览确认；按适配器组织有界列表；展示真实保存序号；撤下重复采集信息和原始策略参数；合并保留切换；空历史不占位、异常统一呈现并保留正确重试路径。保持清理通道、保护、默认开关及持久化格式；管理查询仅增加可选保存序号，不修改 Worker 上报协议。实现涉及 Worker 的本地材料核验，无新数据库迁移。

用户追加：缓存页提供“定期清理”和“空间不足时清理”两个管理员开关，分别持久生效并真实回显。复用 protect 命令的受限 policy 分支及已有 capability 标记，无新表或迁移；只允许两个布尔字段，不改其他保护和阈值。此次手工和本机复测仅覆盖两开关，沿用既有 CI 门禁，排除 #129、不合并。

独立审查后追加限定修复：开关文件损坏时仅暂停自动清理而不阻断节点；节点能力回退时策略命令明确失败并释放管理入口；删除旧自动证明的无用参数与分支。第 4 项格式演进不调整，严格读取与缓存保护保持；只做对应专项测试并更新原验收环境，无新依赖或数据库迁移。
