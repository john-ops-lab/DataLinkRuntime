## Purpose

定义 Token 与账号入口托管文件上传的共同边界，将代理总请求体与后端净文件、配额和流式读取策略分开验证，确保合法大小可穿过代理，超限有明确拒绝层，策略调整无需动态修改代理且不会遗留失控文件。

## ADDED Requirements

### Requirement: 托管上传采用固定有界请求总量
两套支持入口的托管上传路由 SHALL 使用覆盖应用最大净文件加受支持 multipart 开销的固定有限总请求上限；MUST 保留认证、账号路径重写和其他 API 限制，不全局无限放开。

#### Scenario: 最大合同与单位一致
- **WHEN** 应用最大净文件为 2 GiB、multipart 开销预算为 256 KiB
- **THEN** 两套路由的总请求上限至少覆盖 2,147,745,792 字节且为有限值，确定性检查验证单位换算和路由范围

#### Scenario: 支持策略动态改变
- **WHEN** 管理员在应用支持范围内调整单文件上限 L
- **THEN** 后端立即依新 L 校验，无需重写或重载代理，代理继续限制有界总量

### Requirement: 净文件边界与失败清理独立成立
后端 SHALL 保留净文件、multipart、配额、磁盘、流式读取与清理合同；验收 MUST 区分代理拒绝与后端业务拒绝。

#### Scenario: 两套代理通过净文件 L
- **WHEN** 经 Token 或账号真实代理上传净文件 L，包含 L 大于 1 MiB 的合法策略
- **THEN** 上传保存成功，真实脚本读取得到独立预期内容和 SHA-256

#### Scenario: 后端拒绝 L 加一
- **WHEN** L+1 的请求总量仍低于代理固定上限
- **THEN** 后端按实际净文件策略明确拒绝，不产生错误绑定或不可回收对象

#### Scenario: 总量越过代理固定上限
- **WHEN** 请求总量越过专用路由的固定上限
- **THEN** 代理有界拒绝，结果不能作为后端净文件校验通过证据

#### Scenario: 其他路由与认证
- **WHEN** 对其他上传/API 路由或无权限/缺少账号 CSRF 的请求进行回归
- **THEN** 各自限制与认证边界保持原合同
