## Context
参见 proposal.md。现有 host Python + LaunchAgent + Colima 模型可复用，但控制器散落在用户数据目录且构建使用可变镜像标签。升级必须保留已有数据，配置与运行记录保留在私有环境。

## Goals / Non-Goals
**Goals:** 本机 CD 可审查、可登记目标、切换前校验、保留用户资产、失败可诊断。
**Non-Goals:** 不引入线上部署系统，不自动合并，不增加产品 API 或修改业务调度协议，不执行自动数据库回退。

## Decisions
- 仓库维护 Python 标准库控制器、VM Bash 部署器、代表性执行探针和安装器。宿主只保存配置、凭据、运行状态及安装副本；复用已有 LaunchAgent，避免新增常驻服务。
- 显式 `select PR`；CLI 配置变更与最终切换用短互斥锁，构建期间允许切换目标。另一个运行锁禁止两个 controller 同时部署。
- 使用每 SHA 镜像覆盖 Compose，记录镜像 ID。源码仅 git archive，不在宿主执行 PR 代码；构建与迁移在无共享目录 VM 内运行。
- Git ancestor 检查加静态 Alembic revision/down_revision 图校验；不执行候选迁移代码来探测兼容性。既有 revision/down_revision 不得改变或缺失；已应用迁移的函数修复不影响本次向前路径，仍受精确 CI 约束。资产校验允许迁移新增默认数据，但不得丢失或改写既有资产。
- 构建后重新查询目标/CI，先判断执行空闲，停 Control（阻止 API、调度器及重试写入），复查执行状态，再停 Worker、Web，备份 PostgreSQL。忙时恢复原 Control 并等待下轮，不中止任务。
- 迁移前持久保存 deployment 事务记录；迁移、启动、真实执行探针、数据快照比较通过后写 success。中断或失败阻止后台自动重试迁移；保留备份及现场，人工修复后显式解除。
- 恢复只使用记录的镜像 ID，且数据库版本与已部署版本必须一致。相同 SHA 不受 CI 重跑影响。

## Risks / Trade-offs
- 业务无独立维护模式 → 空闲检查与停 Control 后二次检查关闭竞态；已有待运行任务时延后更新。
- 数据库备份不包含材料卷 → 部署不删除材料卷；退役重复环境时另存卷备份并保留原卷。
- Git 与迁移图仅证明可前进，不证明业务兼容 → 仍以精确 CI、备份、数据资产对比、真实执行作为切换证据。
- VM 内存有限 → 串行构建；旧环境退役前先保全其用户数据。

## Migration Plan
备份已有本机控制器；安装并接管旧状态和镜像；登记目标 PR；在既有环境执行受控升级并验证原数据；备份和迁移重复环境的用户资产后停止重复应用。控制器代码可恢复备份，业务数据库不自动降级。
