# B8 接收记录与集成审查

本批将接收记录放入适配器原“执行记录”页签，首屏展示事件来源、待处理/失败数量、时间、来源摘要、处理结果及执行关联。当前问题可定位到阻塞事件、进入受限代码修复；原失败与后来重新处理的每次执行分别保留。Kafka 来源位置、Kubernetes 对象名称/变化及批次阶段用于摘要，不猜测或解析任意业务正文，因此不会把示意图中的订单号当作通用字段。

来源身份、接收时运行配置、原始位置 JSON、容量/留存与高级处置移入技术详情；容量使用可读单位。原 replay/skip/reset/abandon 权限、请求幂等、期望责任和确认规则未改。Kubernetes 未闭合批次可见，成功闭合/人工放弃仍拒绝新 completed replay；人工放弃保持“业务结果未确认”。停止接收与停止当前执行仍是两个明确动作。手动测试入口保留在事件模式的手动测试输入中，仍通过原运行锁并使用已保存输入。

删除已无生产引用的全局订阅页面和旧嵌套面板，将相关能力可见性测试迁到当前来源组件，避免只验证废弃入口。目录状态加载失败不变成零问题；接收停止按钮在目录刷新失败时仍可用，新启用继续阻断。源配置受当前运行锁约束，来源/代码保存和开启接收分离。
