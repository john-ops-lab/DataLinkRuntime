## 当前结论

- 四种来源在原适配器工作区可配置，保留原顶部两入口、四页签和普通任务操作；未知类型无 fallback。公共 registry 规定配置/身份/能力/确认/恢复/shard 预算，原 Kafka/K8s 身份与 batch 完成/放弃/闭合重放规则保持。
- RabbitMQ 4.3.5 / AMQP 0-9-1 / Pika 1.3.2：真实 TLS 及账号、已有专用持久队列、passive 诊断、单条未确认预取、T1 后确认、提交前与确认丢失重投、超限组装前关闭均有直接证据。必须由发送方设置稳定 message_id，产品不创建来源队列。
- RocketMQ 5.3.3 / 5.x Proxy SimpleConsumer / 官方 5.1.2 协议定义：真实收发、ACK、不可见重投、设置流更新与关闭通过。普通消息及单 topic/专用组；4.x、FIFO/事务/Lite、云厂商专用协议不在本轮范围。TLS/签名由本地协议服务器验证，真实 Broker ACL 未验收。

## 首败与修正

保留所有首次失败日志，不重写首次结果。重要修正如下：

1. 官方高层 RocketMQ 客户端无界网络配置不满足预算，改为官方协议定义 + 有界同步 transport；真实 Proxy 要求设置流、长轮询至少 5 秒、不可见时间至少 10 秒。
2. Pika 原始断流缺少终止原因、组装前异常被 SDK 包装均在真实测试中暴露并修正；日志过滤只影响源线程，内部执行队列保留日志。
3. Chrome 中原样保存 TLS 配置曾误报需要新 epoch。原因是 PEM 末尾空白被表单去掉；新来源身份比较统一忽略边界空白，实际信任变化仍需确认。对应合同与双语文案回归通过；部署后原样保存/测试成功、旧 epoch 和事件保留。
4. 其余首次失败来自测试夹具缺少环境参数、英文断言、镜像计数漏计项目本身及验收脚本错用 trigger_type 字段；均修正夹具/验收脚本并复验。真实成功责任未抹除或用新环境覆盖。

本轮无独立审查/远端 CI/生产发布或用户验收结论。开发示例、来源容器、必要 CA/私有配置和首败证据保留；用不上的探针虚拟环境、失败构建源码副本及临时 UI 夹具已清理。
