# Spec Delta

## Purpose

定义适配器目录中的批量启停合同，使用户能够选择明确对象、预览具体动作、逐项查看真实结果，并在失败、断线或刷新后安全恢复操作，而不改变原有运行规则和数据处理责任。

## ADDED Requirements

### Requirement: 选择范围可见且有界
目录 SHALL 支持勾选、全选当前可见列表和清空选择，显示选择数量；筛选或权限变化 SHALL 清除隐藏或不可操作项。每批 MUST 包含 1 至 100 个不同适配器，不得隐式选择所有搜索结果、截断目标或启动无限并发。

#### Scenario: 筛选隐藏已选项
- **WHEN** 用户改变搜索或筛选条件，使部分已选项不可见
- **THEN** 隐藏项从当前选择移除，提交只包含此刻可见且明确选中的项

#### Scenario: 空选择与超限
- **WHEN** 选择为空或超过 100 项，或请求含重复适配器
- **THEN** 客户端说明限制且服务端拒绝整个非法请求，不静默丢项

### Requirement: 动作沿用各运行方式语义
系统 SHALL 根据冻结的运行方式解释启动与停止：手动运行一次或取消选定执行；定时只启停调度；Webhook 只启停新请求接收；事件模式只启停新事件接收。启停 MUST 保留已接收数据与已有执行责任，不修改 Worker、凭据、运行方式或保存用户草稿。

#### Scenario: 混合启动
- **WHEN** 同批包含有效的手动、定时、Webhook 与事件适配器
- **THEN** 手动项创建一次执行，其余项只启用已有配置，定时项不额外立即运行

#### Scenario: 停止接收
- **WHEN** 停用定时、Webhook 或事件模式
- **THEN** 停止新调度或新接收；原有执行和积压按既有规则继续处理，不清空或取消

#### Scenario: 工作副本有修改
- **WHEN** 用户在编辑区保留未保存代码或运行设置后执行批量操作
- **THEN** 操作只使用已保存内容，草稿及当前工作台导航保持不变

### Requirement: 配置与取消目标固定
系统 SHALL 在列表提供已保存配置的校验标识，并在准备及执行每项时核对；准备后 MUST 固定动作、相关配置事实和手动停止的全部当前未完成执行 ID。名称、在线状态等无关变化不构成配置冲突；配置、来源激活身份变化 MUST 逐项拒绝，不重新解释动作。

#### Scenario: 准备后配置改变
- **WHEN** 已保存输入、代码、Worker、触发配置或运行方式在准备后变化
- **THEN** 该项返回配置冲突，不使用新配置，不覆盖已有配置；使用新配置必须明确创建新操作

#### Scenario: 旧执行结束且新执行出现
- **WHEN** 冻结的手动执行已结束，而同一适配器后来创建了新执行
- **THEN** 只核对冻结执行的已结束状态，不取消新执行，不把自然结束描述成已取消

### Requirement: 逐项鉴权与独立提交
系统 SHALL 对每项在执行前重新检查当前用户权限与既有运行门禁，每项独立提交，单项失败不回滚或阻塞无关项。仅可查看对象不得出现可执行入口；不可见对象及已撤销权限的结果 MUST 不泄露名称、配置、执行或来源信息。

#### Scenario: 部分失败
- **WHEN** 同批包含有效、配置不完整、只读和运行冲突对象
- **THEN** 可执行项完成其动作，失败项提供安全原因，各项结果完整保留

#### Scenario: 准备后权限撤销
- **WHEN** 用户准备操作后失去目标访问权限
- **THEN** 执行与结果查询均重新鉴权，该项不执行且详情被隐藏

#### Scenario: 批次中途账号降权或停用
- **WHEN** 前一项完成后账号被停用或管理员角色被撤销
- **THEN** 后续项按当前账号状态与权限执行，不沿用批次开始时的管理员权限

### Requirement: 操作与结果具有持久幂等身份
系统 SHALL 使用客户端稳定操作 ID 和冻结请求识别同一操作；同一 ID 不同请求 MUST 拒绝。单项变更与结果记录 MUST 原子提交；重复执行、双击、提交后响应丢失、刷新或服务重启不能重复创建手动执行或来源激活。

#### Scenario: 提交成功但响应丢失
- **WHEN** 单项动作已提交后连接断开
- **THEN** 查询原操作 ID 返回已提交结果；继续原操作只处理尚未提交项，已成功项不重做

#### Scenario: 竞争执行同一批次
- **WHEN** 多个请求同时执行或重试同一个批次
- **THEN** 同一批次只允许一个协调请求执行单项变更，其他请求可查询结果但不并发重复执行

#### Scenario: 提交结果无法确认
- **WHEN** 数据库连接或提交返回异常，系统无法判断事务是否已提交
- **THEN** 不把该项写成明确失败，先查询原操作回执，不能覆盖已经提交的结果或重复执行

### Requirement: 失败重试保留原意图
系统 SHALL 只允许明确失败且仍可操作的项重试，并重新校验原冻结配置；成功、已受理、正在停止或结果未知项 MUST 不自动重试。查询失败须呈现结果待确认，不将其当作动作失败；配置变化后的尝试必须创建新操作。

#### Scenario: 只重试失败
- **WHEN** 部分项成功，部分因可恢复门禁失败，用户选择重试失败项
- **THEN** 只重新处理仍符合冻结条件的明确失败项，成功项的执行 ID 和结果保持不变

#### Scenario: 状态未知
- **WHEN** 网络错误使客户端无法确认请求结果
- **THEN** 客户端只提供重新查询原操作，不能换新 ID 自动提交或将未知项纳入失败重试

### Requirement: 结果区分受理与实际停止
逐项结果 SHALL 展示具体动作、受理或停止进度、无需变更、失败及原因，并可通过操作 ID 刷新核对。事件停止 MUST 等真实监听关闭才报告已停止；手动创建只报告已提交执行，取消请求与实际终态分开，不能宣称回滚外部写入。

#### Scenario: 监听尚未关闭
- **WHEN** 事件停止请求已提交但原监听尚未确认关闭
- **THEN** 该项显示正在停止；确认关闭后查询才显示已停止接收，积压不受影响

#### Scenario: 目标状态已满足
- **WHEN** 启停项已达到目标且没有待处理故障
- **THEN** 返回无需变更，不重复监听、调度或重置来源

#### Scenario: 来源需要修复
- **WHEN** 启用项处于 blocked、repair 或缺少身份验证
- **THEN** 返回具体原因并引导既有配置/处理页面，不自动修复、重置或跳过消息

### Requirement: 兼容现有使用与可访问性
批量入口 SHALL 置于原适配器目录，保留单项操作、选择名称导航和草稿体验，提供中英文动作与结果、键盘可达的复选框和结果面板。刷新恢复信息 MUST 按账号隔离且仅保存操作标识，不保存输入、凭据或配置正文。

#### Scenario: 刷新与账号切换
- **WHEN** 用户刷新页面或切换账号
- **THEN** 当前账号可重新查询自己的最近操作；其他账号不能通过恢复记录读取或操作原批次
