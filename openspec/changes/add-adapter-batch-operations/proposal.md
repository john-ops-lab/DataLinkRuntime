# Proposal

## Why

适配器数量增加后，维护与恢复需要反复进入详情启停。Issue #223 要在现有目录完成多选和批量操作，同时保证每种运行方式的含义、权限、输入快照与停止边界不变。

本次实施基线为已合并 #219/#221 与 #224 的 main `7750e704f72095f50eaca316019e4c87c29c98e5`；用户已明确授权开始 #223 并提交 PR，Issue 建单时的“仅规划”阶段已经结束。

## What Changes

- 目录增加勾选、全选当前可见项、清空选择和批量启动/停止，筛选后清除隐藏项；中英文沿用现有使用习惯。
- 操作前展示每项具体动作：运行一次、取消本次选定执行、启用/停用定时、开启/停止接收。只使用已保存配置，不保存编辑草稿。
- 增加持久批量操作记录及逐项结果，冻结配置校验标识和手动取消目标；每项独立鉴权、校验、事务提交，支持部分成功、结果重查和只重试明确失败项。
- 固定每批 1–100 个适配器；首期同一批串行处理单项变更（并发为 1，低于 Issue 建议上限 5），继续遵守运行锁、Admission 与监听额度。
- 真实区分已受理、正在停止、已停止、无需变更、失败和结果待确认；刷新与响应丢失不重复创建执行。
- 非目标：批量删除/改配置/发布、工作流编排、多 Worker/HA、#222 容量压测、扩展事件来源和 #219 的整体归档。

## Capabilities

### New Capabilities

- `adapter-batch-operations`：适配器批量动作的选择范围、冻结计划、逐项事务、幂等恢复、权限与结果呈现。

### Modified Capabilities

无。现有输入配置与执行快照合同原样复用；#219 尚未同步的事件来源 delta specs 作为已合并实现的补充合同阅读，不在本变更中重复迁移或归档。

## Impact

- Web：AdapterCatalog、独立批量操作结果面板、API/types、双语文案与针对性测试；不改变工作副本、当前适配器或实时日志导航。
- Control：新增批量 API、两类操作记录、配置校验标识；复用现有执行创建/取消、定时/Webhook 状态切换及事件监听生命周期服务。
- 数据库：在 0049 后增加向前迁移，仅创建操作记录表，不改写旧业务数据。应用回退保留新增表和原卷；不得通过降级/恢复旧库丢弃执行或接收责任。
- 部署：相关 CI 通过后更新已有私有开发测试编排，保持数据库、Token、Master Key、卷与挂载；PR 不自动合并。无新增依赖，无公开凭据、输入内容或私有部署参数。
