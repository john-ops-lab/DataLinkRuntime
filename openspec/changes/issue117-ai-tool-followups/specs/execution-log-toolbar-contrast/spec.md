## Purpose

保证执行记录历史日志与实时日志在各自正常显示模式下都具有清晰、稳定且可访问的工具栏，避免背景与图标同色导致关键操作不可发现或不可使用。

## ADDED Requirements

### Requirement: 历史日志工具栏可见
执行详情中的历史日志工具栏 SHALL 使用与日志正文分离的表面颜色，并 MUST 让搜索框、复制、下载、全屏和恢复控件在默认、悬停、键盘聚焦及可用状态下清晰可见。深色日志正文不得把工具栏表面覆盖为与深色图标近似的纯黑色。

#### Scenario: 打开历史执行日志
- **WHEN** 用户从执行记录打开一个包含日志的执行详情
- **THEN** 搜索框及所有适用的工具栏按钮 MUST 在不悬停的默认状态下可辨识且可操作

#### Scenario: 切换全屏与恢复
- **WHEN** 用户在历史日志中进入全屏并随后恢复
- **THEN** 工具栏表面、图标可见性、搜索内容和可用操作 MUST 在两种布局间保持一致

### Requirement: 可访问对比度与焦点
工具栏文字和图标与其背景之间 MUST 满足适用的 WCAG 2.1 AA 对比度：普通文字至少 4.5:1，必要的非文本图标和焦点指示至少 3:1。所有图标按钮 MUST 具备可聚焦的可访问名称，且 `focus-visible` 指示不得依赖颜色难以分辨的细微变化。

#### Scenario: 键盘遍历工具栏
- **WHEN** 用户只使用键盘依次聚焦搜索框和每个可用按钮
- **THEN** 当前焦点 MUST 始终可见，按钮 MUST 暴露本地化名称，且操作顺序与视觉顺序一致

#### Scenario: 中英文界面状态
- **WHEN** 系统语言分别为 `zh-CN` 和 `en` 并展示历史日志工具栏
- **THEN** 两种语言下的文字、Tooltip 或可访问名称 MUST 正确，且控件不得因文案长度产生遮挡或横向溢出

### Requirement: 实时日志视觉和交互回归保护
修复历史日志时，系统 MUST 保持当前实时日志的底部、全屏和恢复视觉效果，并 SHALL 让历史与实时工具栏复用同一语义颜色和交互状态合同，而不强制两种日志正文使用相同背景。

#### Scenario: 历史修复后查看实时日志
- **WHEN** 用户启动 Execution 并在底部实时日志、全屏日志和恢复布局之间切换
- **THEN** 搜索、复制、下载、暂停或继续、全屏及恢复等适用功能 MUST 保持既有行为，工具栏不得出现纯黑回归或不可见按钮

#### Scenario: 历史和实时日志并行回归验证
- **WHEN** 同一语言和视口下分别呈现历史日志与实时日志
- **THEN** 两者工具栏 MUST 使用一致的可访问语义状态，且各自日志正文主题和现有实时日志效果保持不变
