## Why

Issue #117 后续实测暴露出四个相互关联的可用性与可审计性缺口：AI 工具预算过早触顶且失败时丢失已有成果，知识库开关不能保证实际检索，工具轨迹不足以复盘，同时历史执行日志的工具栏对比度回归导致按钮不可见。现在需要在保留实时日志既有效果和 AI 安全边界的前提下，形成可验证、可回滚的统一修复合同。

## What Changes

- 将单次 AI Assist 的工具预算从 4 轮 / 8 次调整为 8 轮 / 16 次，并增加重复调用检测、连续失败保护与 120–180 秒总时限；达到任一边界时，使用已获得的安全结果强制进入最终回答，而不是丢弃轨迹并只返回上限错误。
- 修复执行记录历史日志工具栏的纯黑背景和深色图标叠加问题，使搜索、复制、下载、全屏与恢复按钮在历史日志和实时日志中都保持可见、可聚焦且具备一致的可访问对比度；实时日志当前交互与视觉效果保持不变。
- 为每次工具调用持久记录成功、失败和触顶路径均可审计的脱敏元数据，包括请求 / 会话关联标识、轮次、工具名、参数摘要、状态、耗时、结果大小与稳定错误码；工具审计日志必须按大小和保留数量或期限轮转清理，避免无界占用存储。
- 工具结果仍执行服务端长度与安全截断，但前端不再展示“结果过大 / 已截断”提示；可见摘要仅以单个省略号 `…` 结尾。
- 勾选“知识库检索”后，服务端 MUST 先执行知识库工具链，再允许模型生成最终回答：先列出知识库、再搜索匹配内容、按需读取正文；失败或无结果时透明说明，并通过去重、失败保护和预算边界避免无意义循环。
- 保持 Secret、Credential、平台 Token、完整 Prompt、Provider reasoning 和原始响应不落盘；审计内容仅使用白名单字段与截断、脱敏后的摘要。
- 非目标：不引入写入型知识库工具、通用 Agent 自动执行循环、外部日志系统、第三方可观测依赖或新的 UI 框架，也不改变 Candidate → Diff → Apply 的人工确认边界。

## Capabilities

### New Capabilities

- `ai-tool-orchestration`: 定义扩展后的工具轮次 / 调用预算、重复与连续失败保护、总时限，以及触边界后基于已有结果完成最终回答的行为。
- `execution-log-toolbar-contrast`: 定义历史与实时执行日志工具栏的可见性、交互保真和可访问对比度要求。
- `ai-tool-audit`: 定义工具调用脱敏审计轨迹、请求 / 会话关联、成功与失败留痕、轮转保留，以及前端省略号截断呈现。
- `ai-knowledge-retrieval`: 定义启用知识库检索时强制优先 list / search / read 的顺序、失败与空结果说明及防循环行为。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已归档的同名 capability；本 change 以四个新 delta specs 建立后续同步基线，不改写 `docs/specs/` 历史合同。

## Impact

- 后端：Control 的 AI Prompt / 工具编排、工具预算与调用执行、知识源适配、响应摘要和平台日志配置；需要补充成功、失败、触顶、超时、重复调用、连续失败与知识库强制路径测试。
- 前端：AI 工具调用卡片、zh-CN / en 文案、执行详情历史日志与实时日志共用组件 / 样式；需要组件测试与真实浏览器双语验收。
- 部署与运维：工具审计沿用自托管平台日志边界并增加有界轮转与清理合同；默认配置必须安全，升级不要求数据库迁移，不保存历史 Prompt 或原始响应。
- 兼容性：现有 AI Assist 请求字段、Candidate 合同、知识源只读权限和 Execution API 保持向后兼容；未勾选知识库检索时维持当前可选工具策略。回滚代码与配置即可恢复旧行为，已生成的脱敏轮转日志可按既有保留策略自然清理。
