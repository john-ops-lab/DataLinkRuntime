# Design

## Context

见 proposal.md。实现以用户确认的 v2 图为视觉依据，保留 assistant-ui External Store Runtime、请求冻结和代码应用状态，使用锁定的 Ant Design 5.29.3。

## Goals / Non-Goals

目标：消除输入区内的帮助展开与多重滚动，明确审查入口，以服务端 locale 驱动代码注释。
非目标：不启用知识库开关、不新增模型选择、历史会话或自动执行，不将概念图里的反馈图标实现为新产品功能。

## Decisions

- 顶部 Dropdown 使用 click、autoFocus 和显式键盘打开；选择预览或帮助后打开有标题、Escape 关闭、恢复焦点到更多按钮的 Modal。相比在输入区展开，独立浮层不会挤走发送按钮。
- 复用发送范围渲染，保留每轮冻结的历史预览；当前预览放在 Composer Runtime 之内读取即时附件。帮助复用实时服务端附件限制和能力说明，格式映射为图片／PDF／Word／Excel／文本与代码。
- 侧栏采用 400–440px 的响应式宽度；最大化通过 CSS 为对话、代码建议、输入设置上限 904px 的居中阅读列，保留同一 runtime 实例。长输入和待发送附件列表限高，发送工具栏不参与滚动。
- 在静态 system.md 写注释质量规则，Prompt builder 根据服务端 locale 注入明确的 Chinese／English 语言指令，不从消息内容猜测。所有重试和生成沿用统一 builder，无需新增传输字段或对模型结果机械插入注释。

## Risks / Trade-offs

- 模型可能不遵循注释要求 → 组装回归之外保留真实 Provider 样例与语法检查；不把提示词测试等同模型行为验收。
- 帮助从常驻变为按需 → 顶部临时对话标识、输入底部单行隐私提示保留可发现性。
- 响应式 CSS 与历史断点冲突 → 在中英文三个桌面宽度、最大化／恢复及长输入附件状态做浏览器验证。

## Migration Plan

无数据库迁移。通过 PR HEAD 的 CI 后，按私有配置选择正确的现有验收编排并验证真实部署 SHA；不重建持久卷、不恢复数据库、不将旧自动控制器状态冒充当前验收状态。
