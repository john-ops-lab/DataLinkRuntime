## 资源及计时限制

平台为独立 4 CPU / 8 GiB Linux VM、无 swap；Control 1 GiB、Worker 整体 2 GiB / 2.5 CPU / 512 PID，原沙箱预检通过。Control 采样全窗 RSS 峰值 409.484 MiB。Worker 采样误用了 Agent 迁移后的叶子 cgroup，精确正式总峰值未知；另行核实配置哈希、完整容器 ID 与专用祖先路径，该祖先包含全部 Worker/沙箱与准备、预热，其累计峰值 183.617 MiB 是正式 Worker 总内存的保守上界，不把叶子读数当整体。后续采样必须读取容器根 cgroup。

435 个资源样本，平均间隔 1.002 s、最大 1.014 s；无 OOM、服务正常退出。最低持久盘可用 33.305 GiB。Control/Worker 诊断各低于 12 MiB，连同资源/账本共约 13.97 MiB，有限聚合计数一致。

UTC 与 monotonic 的关系在正式窗也变化约 1.613 s；阶段耗时只使用同 VM 单调时钟，不以跨 VM UTC 差宣称精确接管 SLA。正式容量将使用同一个外部发生器单调时钟的保守上下界，并独立核对服务端实际状态。
