# B4 HTTP 发生器资格与计时方法

## 范围与已发生的失败

本方法限定在仓库外的隔离发生器及其夹具，不修改 DLR 接收合同、期望数量、平台资源、目标或 5/60/600 秒门槛。正式 HTTP 配置固定 125 个实际请求名额、0.5 CPU、512 MiB；工具通用配置仍为 1–128、缺省 128。

第一轮真实 HTTP 发生器只首发 375/10,000 条，9,625 条未发，77 次首发结果不明、1 次 408，最终 374 条确认接收。随后在相同资源预算、同进程 loopback 即时响应 peer 上，原 HTTPX/逐 ID 任务路线仍只首发 426 条，9,574 条未发、54 次结果不明。该无 DLR 对照复现了发生器首发失败；这些结果不能作为 DLR 一万条容量结论。原失败、源码/依赖及逐轮原始证据保留，不通过重置 T0、减数量或增加资源消除失败。

## 客户端与调度合同

- 使用公开 aiohttp 3.14.5 客户端和固定工具依赖；连接池、读取及解析受限，不自行实现业务 HTTP 客户端解析器。TLS 验证保持，关闭环境代理、重定向、自动解压及隐藏请求重发。
- 仅保留有限工作协程和有界任务队列。首发优先；重试/已知记录查询只保存至多每 ID 一份的延迟状态，等待不持请求名额，不为一万条 ID 同时创建等待任务或计时器。
- 首次发送仍必须在原起点后 5 秒内实际开始；创建状态、排队和申请工作名额不算发送。截止时明确登记未发 ID，不在之后补作迟到首发；全部 ID 已开始或已登记未发后才开放查询和重试。
- 同一 ID 最多 20 次 POST、整轮 60 秒，每请求最多 5 秒并受剩余总窗约束。429/503 遵守 1–30 秒整数 `Retry-After`；未知结果仍使用原 ID/原文，仅已知接收编号可查询固定来源下的该记录。
- 首发后的 POST/查询共享 500 次实际开始/秒的平滑门，等候不占 HTTP 名额，空闲或事件循环停顿后不补发积攒的令牌。首发旁路保持；不附加指数退避或 3 秒下限，遵守 Retry-After 下限，20 次/60 秒及首发 5 秒合同不延长。
- 完整读取响应后归还实际请求名额；正文最多 16 KiB，响应头/缓冲有界。保留原日志、结果文件预算和独占创建规则。首发状态、未知、重试、查询及实际发送时刻分别记录；请求工作峰值、连接池大小或排队数不能替代实际请求计数。

## 两层验证

先以纯测试核对大量首发拒绝不导致屏障死锁、退避不占名额、查询不抢先、任务和延迟状态有界、首发截止、20 次/60 秒、未知同 ID/原文恢复、取消清理、响应大小、重定向/隐藏重发与日志上限。普通 RabbitMQ 生成、发布确认及独立目标 oracle 的合同保持。

随后由验收控制器在原发生器预算内运行一个同进程 loopback HTTP/1.1 keepalive peer：限制 125 个连接，完整读取固定 2,048-byte 正文后立即返回固定合法 202/接收编号/状态路径，响应及头各受 16 KiB 限制；只运行 200 和 10,000 条，各轮至多 65 秒，并核对真实资源边界和工作数量。peer 不执行数据库、业务逻辑或人为延迟，不连接真实 DLR、Broker 或目标。仅输出脱敏聚合；正式发生器的 ID、原文和凭据不进入公开材料。

必须明确：client 与 peer 共享同一份 0.5 CPU/512 MiB，所得耗时包含两者成本；资格预检不是单独的客户端成本分解，更不是产品容量结论。只有同预算预检证明一万条均在原 5 秒内首发、结果及 60 秒预算可核验后，才冻结新源码/依赖清单和管理探针哈希绑定，重新进入真实 DLR 容量轮次。loopback 中使用聚合 sink 时还须披露未包含逐条磁盘 flush 的差异，不能据此宣称正式日志成本已经验证。

2026-10-26，冻结候选 `c6bc1952a13c7d367fbf8c5ee45c3601d93b4529` 已补真实 PrivateLog 的两轮资格预检：200条首发0.083411秒、整轮0.099373秒；10000条首发2.018958秒、整轮2.795987秒，均低于65秒整轮限制。两轮均读回0.5 CPU/512MiB/swap0、125个请求名额；peer完整读取各200/10000条固定正文（409,600/20,480,000 bytes）并返回相应数量合法202，无unknown或缺失。真实逐条编码/写入/flush以及结果文件写入、哈希读回均执行；10000条逐条日志约1.53MB、append累计墙钟约0.350秒，此处flush不等于fsync。随后真实DLR的正式r4仍首发9352条、实际接管4073条，容量FAIL；资格预检通过不能替代接收侧验收。

上述两轮直接调用冻结工具的真实 PrivateLog.append 与 write_result。先前聚合sink记录继续保留“未含真实逐条日志”的边界，不将其与新资格记录混同；工具纯测试、真实日志资格与产品容量分别裁决。

正式 DLR 轮次继续使用完整日志和原管理/资源/双 oracle、接管 60 秒、排空及排空后完整 600 秒门禁；HTTP 首轮成功/拒绝比例、未知及补发次数均披露。任何必要门禁失败都保留首败，并先定位相应工具或产品边界，不提前填写容量、OCR 或用户界面通过。
