# Spec Delta

## MODIFIED Requirements

### Requirement: 创建和来源配置不自动开启接收
新建流程 SHALL 沿用原入口、模板入口、名称和语言选择，允许选择事件触发并为新建适配器配置已通过交付门槛的 Kafka/Kubernetes/RabbitMQ/RocketMQ/HTTP 来源。界面 MUST 不另要求订阅名称，不增加持久 Adapter 类型或运行枚举。取消来源配置 SHALL 保留已创建适配器且不启动接收。来源保存、代码保存、连接或配置校验与明确开启 SHALL 独立；校验 MUST 不执行业务，首次开启仍校验已保存代码、Worker、配置与原运行锁。

#### Scenario: 创建后取消来源配置
- **WHEN** 用户创建事件触发适配器后取消配置来源
- **THEN** 已创建适配器仍可编辑和继续配置，没有启用订阅、监听或自动业务执行

#### Scenario: 首次起点和必填高级字段
- **WHEN** 用户配置 Kafka 首次范围但未明确选择起点，或高级区仍有无效必填字段
- **THEN** 表单阻止保存，展开并聚焦对应项；不会静默选择历史/最新起点，也不通过隐藏字段漏掉认证校验

#### Scenario: 配置被动 HTTP 来源
- **WHEN** 用户在适配器运行设置选择已交付的 HTTP 来源并校验路由/凭据配置
- **THEN** 不启动模拟消息或业务执行，不把它包装成 MQ 连接测试；保存与开启分别操作，顶部仍无独立事件订阅菜单

## ADDED Requirements

### Requirement: 平台容量上限与入口配额有独立权限和生效边界
接收容量 SHALL 由部署管理员设置平台上限，入口 limits 按 Adapter edit 权限和期望配置版本管理且不得越过平台上限。入口修改 MUST 停用、确认关闭并排空；首期不提供带积压的热调额 API。平台配置变更 SHALL 校验并记录有效指纹和审计、在重启后生效；无效配置不得启用新接收，仍保留旧责任和管理处置能力。

#### Scenario: 普通调用方提高平台上限
- **WHEN** 只有入口编辑权限的调用方通过配置 API 提交高于部署上限的额度或尝试改全局配置
- **THEN** 请求被拒绝，不改变其他入口额度或已有计数，不启动接收

#### Scenario: 带积压修改本入口额度
- **WHEN** 入口已停用但旧责任仍未结清，用户试图修改 limits
- **THEN** 按现行排空合同明确拒绝；既有受限 repair、处置和继续处理旧责任的路径保持

#### Scenario: 全局配置下调后超过额度
- **WHEN** 合法部署调整使现存责任超过新全局上限
- **THEN** 保留计数、原始数据、失败和控制预留，停止新接管并显示原因，不用清理历史或伪造空闲额度完成配置生效

#### Scenario: 接收进程的配置指纹不一致
- **WHEN** 某接收进程的本地 profile 与平台持久生效指纹不一致
- **THEN** 该进程停止新接管并报告配置原因，不按另一套额度接收，管理与旧责任结算仍可继续

### Requirement: 被动接收沿用激活所有权和停用责任
HTTP 来源 SHALL 使用有效激活及所有权进行接管，停用/配置切换的事务边界与旧来源一致。旧 owner、功能开关、激活失效或容量等待 MUST NOT 新增消息坏记录；来源配置与凭据引用的修改继续受运行锁约束，不能使旧消息改用新版本或新节点。

#### Scenario: 在途 HTTP 请求遇到停用或 owner 变化
- **WHEN** 请求已读入但接管前所有权或启用状态变化
- **THEN** 未提交请求明确拒绝且不记为消息损坏；已提交责任可查询并继续排空，不需要 reset 才能恢复

### Requirement: 接收容量和处理进度在适配器内可理解呈现
工作台 SHALL 用中英文普通用户文案区分已收到、等待处理、处理中、处理成功和处理失败，展示积压数量、最老等待及当前可行动原因。内部字节配额、原始位置和阶段指标 SHALL 可在技术详情查看；批量启停和现有运行方式保持原含义，不因来源增加自动保存草稿或切换节点。
接收记录单次分页响应的总数与记录集合 SHALL 来自同一数据库快照；权限、来源范围、降序游标和空页总数含义保持，不能因并发接管返回总数小于本页条数。

#### Scenario: 入口因容量暂停且仍在处理旧数据
- **WHEN** 新接收暂停而已有消息仍在排空
- **THEN** 页面分别说明接收暂停和旧消息处理进度，不把平台等待显示为消息损坏或全部处理完成

#### Scenario: HTTP 额度用尽时仍查询原记录
- **WHEN** HTTP 入口的持久容量已用尽，新的 ID 被拒绝，而原 ID 与原文再次提交或查询
- **THEN** 原记录仍按既有幂等合同可读；管理响应的可选 `capacity_paused` 只读提示依据本入口及全局额度（含预留）、现有低水位和最老积压，不含瞬时速率窗口，不写错误、坏消息屏障或配额账本，也不参与接管判断；页面提供容量说明和原详情入口，真实故障、修复和停用优先，未提供该字段的旧后端保持原显示
