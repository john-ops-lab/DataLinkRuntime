## Purpose

让账号资料与用户管理页面在信息层级、操作布局和状态反馈上与 DLR 主工作台一致，并以可在浏览器验证的结构改善可读性，同时完整保留既有账号、角色和权限功能。

## ADDED Requirements

### Requirement: 账号页面使用统一的工作台信息层级

账号资料与用户管理页面 MUST 使用一致的页面标题、说明、主操作区、卡片/表单/表格层级、按钮与图标语义、间距和状态标签；空状态、加载中、成功和错误反馈 SHALL 在相同交互位置以明确可读的方式呈现。页面在受支持桌面宽度下 MUST 不产生主要内容的水平溢出。

#### Scenario: 打开账号资料页
- **WHEN** 用户进入账号资料页面
- **THEN** 标题、说明、资料表单、修改用户名/密码操作及成功或错误反馈按主工作台一致的层级和间距呈现

#### Scenario: 打开用户管理页
- **WHEN** 具备相应权限的用户进入用户管理页面
- **THEN** 用户表格、创建入口、角色/状态操作、批量操作、空状态和反馈区域按统一工作台视觉结构呈现且主要内容不横向溢出

### Requirement: UI 优化不改变账号与权限行为

页面视觉调整 MUST 保持修改用户名、修改密码、创建用户、角色调整、启停、重置密码、批量操作及现有权限判定的请求语义和结果语义；不得通过 UI 重排引入额外权限或改变成功/失败处理。

#### Scenario: 既有账号操作继续可用
- **WHEN** 用户通过优化后的页面提交用户名或密码修改
- **THEN** 请求仍按既有认证与校验合同处理，成功和失败反馈清晰且不回显敏感值

#### Scenario: 管理员执行用户管理操作
- **WHEN** 管理员执行创建、角色调整、启停、重置密码或批量操作
- **THEN** 操作仍遵守原有权限和后端结果，不因布局或按钮样式变化而放宽或缩小授权范围
