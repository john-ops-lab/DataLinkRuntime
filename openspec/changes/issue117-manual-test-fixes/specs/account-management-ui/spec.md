## Purpose

让账号资料与用户管理页面在信息层级、操作布局和状态反馈上与 DLR 主工作台一致，并以可在浏览器验证的结构改善可读性，同时完整保留既有账号、角色和权限功能。

## ADDED Requirements

### Requirement: 账号页面复用可检查的工作台基线

账号资料与用户管理页面 MUST 复用 DLR 现有工作台的页面容器、卡片/表单/表格/状态组件和间距 token，并以同一视口下的 Adapter Catalog/Workbench 作为明确对照基线。标题、说明和主操作区 SHALL 位于与该基线对应的页面头部、内容区和操作区；成功/错误反馈 SHALL 保留在触发它的表单或行操作附近的既有反馈区域，加载中/空状态 SHALL 位于同一内容区域。页面在 `1280/1440/1680/1920` 宽度下 MUST 满足主要内容 `scrollWidth <= clientWidth`，不得产生水平溢出。

#### Scenario: 打开账号资料页并对照工作台
- **WHEN** 用户在目标桌面宽度进入账号资料页面并与同宽度 Adapter Catalog/Workbench 对照
- **THEN** 页面复用同一类容器/卡片/表单/状态组件，标题、说明、主操作和反馈处于对应区域，且主要内容 `scrollWidth <= clientWidth`

#### Scenario: 打开用户管理页并对照工作台
- **WHEN** 具备相应权限的用户在目标桌面宽度进入用户管理页面并与同宽度 Adapter Catalog/Workbench 对照
- **THEN** 用户表格、创建入口、角色/状态操作、批量操作、空状态和反馈区域位于对应容器/操作区，且主要内容 `scrollWidth <= clientWidth`

### Requirement: UI 优化不改变账号与权限行为

页面视觉调整 MUST 保持修改用户名、修改密码、创建用户、角色调整、启停、重置密码、批量操作及现有权限判定的请求语义和结果语义；不得通过 UI 重排引入额外权限或改变成功/失败处理。

#### Scenario: 既有账号操作继续可用
- **WHEN** 用户通过优化后的页面提交用户名或密码修改
- **THEN** 请求仍按既有认证与校验合同处理，成功和失败反馈清晰且不回显敏感值

#### Scenario: 管理员执行用户管理操作
- **WHEN** 管理员执行创建、角色调整、启停、重置密码或批量操作
- **THEN** 操作仍遵守原有权限和后端结果，不因布局或按钮样式变化而放宽或缩小授权范围
