## Context

三种语言已有版本隔离环境及原生 uv/npm/Maven 安装路径。现有环境缓存不区分来源；内置源必须采用内容身份隔离，不能复用未知来源包。

## Goals / Non-Goals

覆盖 #141 的文件管理、总容量、严格离线安装、占用保护、指定 Worker 检查。无需替代包管理器，不包含新语言、镜像同步、单 Adapter 选源或包撤销。

## Decisions

- PostgreSQL 保存文件元数据、上传预留、容量配置和任务材料快照；Control 专用目录保存正文。上传先预留容量再流式接收并校验，全部类别共用锁与配额。文件锁区分活跃流与中断上传；无法证明空闲时保留预留。
- 支持 wheel、npm tgz、Maven 仓库相对路径下的 JAR/POM/metadata XML。只做有界元数据检查，不运行上传代码。Maven 安装材料必须含原生 dependency plugin 与传递依赖。
- 接受任务时冻结该类别已保存材料的 ID、路径、大小、SHA-256；删除与快照通过同一库锁排序。接受但未结束的任务均占用材料，采取保守整类别快照避免自研依赖解析器。
- Worker 经现有 Worker/Claim 认证下载，认证仅保留在 Worker 下载客户端，不传给包管理器。下载全部校验后使用本地材料；uv 离线 wheelhouse、npm 本地只读 registry、Maven 隔离 local repository 离线模式。
- 缓存身份包含内置源及文件摘要；直接 URL、安装选项、外部 npm 引用不能绕过源选择。适配器业务网络不受影响。
- 删除先持久标记 deleting，正文移除成功后删元数据。失败保留可重试状态并明确返回失败；不存在恢复副本。下载用共享文件锁，删除用非阻塞独占锁。

## Risks / Trade-offs

整类别快照保守占用与下载可能较大，但它不猜测跨语言依赖图，缺依赖由真正安装检查确认。离线源仅接受可验证材料；Python 需要匹配 Worker 的 wheel，Java 构建插件同样需要提前准备。未知中断状态不能靠超时假设安装停止。

## Migration Plan

迁移新增库表及 nullable 任务快照字段，种入三条非默认内置源。Control 部署持久目录。先升级 Control 与 Worker，再手动选择内置源。回滚按操作文档关闭选择、排空任务并保留一致备份。
