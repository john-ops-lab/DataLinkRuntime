## Context

见 proposal.md。现有模板目录、普通适配器保存 API 和编辑草稿机制可以复用，主要变化跨 Web、Control 和静态资源。

## Goals / Non-Goals

**Goals:** 用现有组件和接口实现 14 项修订，避免用户绕过检查保存即得到可运行版本；源码示例与元数据哈希保持一致。

**Non-Goals:** 不重做 UI 框架，不扩大模板质量审计，不修改可靠运行时合同，不在人工测试通过前发布 PR。

## Decisions

1. theme 可省略表示全部。比增加伪主题更直接，主题目录保持真实分类。
2. 后端删除成熟度类型和 Receipt 机制，API 删除不再展示的合同字段。语言集合由严格三项改为非空子集，目录继续验证源码资源和哈希。
3. 原子复制仅写 Adapter、Slot 和类型配置。Web 将已取得的源码/依赖放入普通编辑草稿，首次保存复用现有版本与 Worker 校验；不在后台悄悄创建 Revision 1。
4. 保留历史来源数据库列兼容既有数据，新副本两列为空；不为移除页面信息增加破坏性迁移。
5. 配置集中在模板代码开头，运行输入仅作真实数据入口或必要覆盖。凭据读法旁写明对应绑定名称；运行模式和数据写入提醒写在相关配置旁。
6. 当前文档改为简短使用步骤，删除失效模板声明，实际依赖声明按其仍适用内容保留。

## Risks / Trade-offs

- 未保存草稿在导航和刷新中可能丢失 → 复用并验证编辑草稿恢复及未保存提示。
- 模板代码改动导致哈希不匹配 → 最终同步哈希并执行发布资源读取和核心源码测试。
- Docker 清理误伤共享数据 → 先检查项目标签、挂载和使用情况，仅清理确认为本项目且无用的临时资源。

## Migration Plan

无新增数据库迁移；前后端同时部署。保留历史适配器和已保存版本。清理后用新测试数据卷启动应用，完成浏览器验收后交用户测试；用户通过后再创建 PR。
