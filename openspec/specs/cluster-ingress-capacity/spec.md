# cluster-ingress-capacity Specification

## Purpose

定义双 Control 的部署级订阅额度、各节点的资源预算以及基于远程 PostgreSQL 容量观测的新接收门禁。容量 provider 的外部高可用和数据库主备切换由基础设施部署另行验证。

## Requirements

### Requirement: 新增 Control 不复制订阅与接收额度
数据库 SHALL 对整个部署统一裁决最多 16 个启用订阅、既有持久责任配额和默认每订阅 10/s、全局 50/s 速率。合法旧责任的读回或重复请求 MUST 保持已有幂等和计费规则。

#### Scenario: 启用、接收和下调竞争
- **WHEN** 两个节点同时争抢最后一个订阅或接收额度，或者管理员下调额度时已有占用超过新值
- **THEN** 数据库只允许取得剩余额度的事务成功，第 17 个启用订阅被拒绝；既有责任保留，后续新增负载按新额度背压。

### Requirement: 节点资源各自有界并为恢复保留资源
双节点首次部署 SHALL 将 HTTP 在途总数限制为 256、HTTP 子预算合计 16 MiB、来源应用缓冲合计 128 MiB、intake 数据库连接合计 16。单节点须能承担全部 16 份 owner 责任。owner 和连接诊断共享有界名额，owner 接管优先。管理及恢复须保留独立连接预算。超出登记容量或指纹不符的节点 MUST 拒绝新的 intake。

#### Scenario: 诊断压力和节点退出
- **WHEN** 一台节点退出，另一台已有连接诊断或工作正在关闭
- **THEN** 在上述总预算内保留接管 16 份 owner 的容量，诊断可返回繁忙。线程、SDK 或本机 I/O 的占用在真实结束后释放；lease 到期本身不释放该占用。具体来源的接管进度按各自协议证明。

### Requirement: 数据库容量样本属于指定域和 epoch
远程模式 SHALL 从固定的受认证 HTTPS provider 读取有界 JSON，校验 schema_version、cluster_id、storage_domain_id、topology_epoch、observed_at 和 writable_free_bytes。观测合同要求保守覆盖可写主库及声明的可提升副本的数据和 WAL 空间。新 ID 的接受事务 MUST 在数据库权威行锁内按数据库时钟重新核实最新状态，采样和获取时间最多 15 秒，采样未来偏差最多 5 秒。单机原部署可继续观测对应本地数据卷。

#### Scenario: 低水位、过期和互相矛盾的样本
- **WHEN** B 更新容量时 A 正在等待 T1 锁，或 A 在重启后收到较旧观测
- **THEN** 两节点沿同一数据库顺序裁决；可用空间 ≤5 GiB 停新接收，停止后达到 6 GiB 才可恢复。旧值不能覆盖新值；同时间戳冲突保持拒绝，直到更新且合法的样本满足恢复条件。

#### Scenario: 观测缺失与旧责任读回
- **WHEN** 容量过期、配置不符、provider 不可达或响应无效，而数据库仍可查询既有责任
- **THEN** 新 ID 被拒绝并返回容量不可用原因，旧 ID、合法幂等重投与结算按原权限继续。Control 本地磁盘和数据库逻辑大小不能替代远程容量证据。

### Requirement: 容量配置离线切换并保留账本
管理员 SHALL 在停新接收、排空原工作、隔离旧运行角色会话后，以部署 owner 切换容量指纹与 epoch；旧样本和旧节点的 intake 权限 MUST 失效。

#### Scenario: 旧配置节点恢复
- **WHEN** 原节点在切换后重新连接，或新节点仍未得到新 epoch 的合法观测
- **THEN** 既有占用和凭据边界保留，旧节点不能启用 intake，新节点获得有效匹配观测且满足恢复阈值和集群预算后才开放新接收。
